ConvexHire — Shortlisting flow

One picture. Job expires → fast filter → AI review → save.

Fast ML filter Tech reviewer People reviewer Judge Final merge (cheap AI) Save to DB

How each cost saver works — with example

1 Filter first with cheap ML

Tiny RandomForest model scores every resume in milliseconds. Only top 20% reach the AI.

without filter Job has 100 applicants. AI reviews all 100. 100 AI calls
→
with ML filter ML scores all 100 (free). Only top 20 go to AI. 20 AI calls · 80% saved

2 Reuse the job text (prompt caching)

Job description + system rules are the same on every call. Bedrock caches them. Cached part bills at ~10% of normal.

without cache Tech + People + Judge + retry. Each call sends full 4000-token job text. ~16,000 tokens billed
→
with cache First call: 4000 tokens. Next 3 calls: 400 each (cache hit). ~5,200 tokens · 67% saved

3 Short answers only (schema caps)

Pydantic limits force the AI to be brief: max 4 strengths, 4 concerns, 120 chars each. No prose paragraphs.

without caps "This candidate is a highly experienced Senior Software Engineer with 7 years of professional experience applying for…" (1500-token paragraph) ~1500 output tokens
→
with caps strengths: ["Strong Python ETL pipelines (resume)", "AWS skills match JD"] ~150 output tokens · 90% saved

4 Stop early when judge is sure

Judge returns confidence 0–1. If ≥0.7, skip the retry loop. Same quality, half the work.

without confidence gate Always loops twice. Two rounds of Tech + People + Judge. 6 AI calls per resume
→
with confidence gate Judge says "satisfied=true, conf=0.85" on round 1 → skip retry. 3 AI calls · 50% saved

5 Use cheap AI for the final merge

Final step just dedupes two lists. No reasoning needed. Switch from Sonnet to Haiku — 12× cheaper.

without routing Sonnet does merge. Costs $0.003/1K input, $0.015/1K output. $0.018 per merge
→
with routing to Haiku Haiku does merge. Same output quality for dedupe. $0.0015 per merge · 92% saved

+ Web search has a 1-call limit + cache

Each reviewer can search the web at most once. Result cached and shared. Big HTML stripped down to 300 chars.

without limit Tech reviewer searches 3 times. People reviewer searches 3 times. Each result is full HTML page in the conversation. 6 searches · ~12,000 tokens of HTML
→
with budget + cache Tech searches once. People reuses cached result. 300-char summary only. 1 search · ~600 tokens · 95% saved

= Combined effect

All five together on one applicant pipeline:

before optimization 100 applicants × full AI review × verbose paragraphs × 2 loops × Sonnet everywhere ~$8.00 per job
→
after optimization 20 applicants × cached prompts × short JSON × 1 loop × Haiku merge ~$0.80 per job · 90% saved
