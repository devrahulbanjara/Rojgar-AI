Severity levels explained

Three levels tell the candidate exactly what to prioritise.

critical Required by JD + clearly absent from resume. Likely auto-filtered.
preferred Nice-to-have. Adds points but not a blocker for shortlisting.
bonus Optional mention. Safe to skip if time-pressed.

Auto-patch — headline & summary rewrite

LLM rewrites using JD vocabulary. Verbatim echo of original = failure mode.

before

after AI patch
Headline: Cloud-Native Backend Engineer · Python · AWS · Distributed Systems
Summary: Backend engineer with 3 years delivering high-throughput Python APIs on AWS. Experienced in PostgreSQL, Docker, and building scalable REST services—ready to move into cloud-native environments with Kubernetes.
🔒 Frozen facts never modified: company name · job title · dates · institution · certifications

Server guardrails — skills capping

Even if LLM suggests 10 new skills, server enforces max 5 new, max 30 total. Existing skills always preserved.

LLM proposes:
PythonDjangoPostgreSQLDockerGit AWS Lambda Kubernetes Terraform Redis Kafka Elasticsearch Datadog
After guardrails (max 5 new, 30 total):
PythonDjangoPostgreSQLDockerGit AWS Lambda Kubernetes Terraform Redis Kafka Elasticsearch Datadog
MAX_NEW_SKILLS = 5 · MAX_TOTAL_SKILLS = 30 · case-insensitive dedup

Pending patch — confirm vs discard

Patch is never written to DB immediately. Staged in Redis for 30 min. Candidate reviews, then decides.

Headline changed: Backend Developer → Cloud-Native Backend Engineer
Skills added: AWS Lambda, Kubernetes, Terraform
Experience at Acme Corp: 3 bullets rewritten with Docker/CI vocabulary
✅ Accept
patch applied to DB · caches cleared
❌ Discard
patch deleted · resume unchanged
